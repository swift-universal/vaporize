What it is

Native Apple tooling, with an assistant-safe proof layer.

Vaporize is not a compiler replacement and it is not a speed claim. It is the owned build, install, launch, project-generation, and release-review lane for assistant-run engineering where the receipt matters as much as the command.

1

Proof-first execution

Build, test, install, validation, and release-review actions route through typed Vaporize surfaces with receipts.

2

Pkl Apple projects

Owned Pkl records can generate first-slice Xcode project world-state instead of relying on stale project YAML as truth.

3

Tool release identity

CLI targets can receive bundle id, marketing version, build number, build metadata, and Sparkle Info.plist keys.

4

Release doctor

A package-local audit checks release docs, JSON evidence, launch-review references, Carrie CMO gate ownership, provenance, and CUJ coverage.

5

Claim discipline

Public-facing copy is constrained by the release packet and cannot outrun benchmark, fleet, or publication proof.

6

Workstream-ready changes

Behavior changes attach to a modification request, targeted tests, release evidence, and explicit proof commands.

How it works

The command is only done when the proof surface agrees.

Vaporize keeps native engines as the execution truth, then records the route, the artifact, the release gate, and the remaining blocker.

Route

Use the owned lane

Assistant work enters through Vaporize instead of ad hoc shell routes.

Execute

Run native tools

Swift, SwiftPM, xcodebuild, PklSwift, and CommonProcess stay the engines of record.

Record

Emit receipts

JSON evidence names commands, artifacts, target facts, product paths, and boundaries.

Gate

Limit claims

Release gates distinguish proven behavior from blocked fleet or public-launch claims.

Public claim boundary

Safe to say in this draft, and not one word past it.

This marketing surface is a draft public disclosure artifact. It can explain the product direction and the proof that exists, but it cannot approve publication or stronger performance claims. Carrie CMO (cmo-chief-marketing-officer-carrie@wrkstrm.occupations.org) owns the consumer-facing publication gate; wrkstrm-core owns the implementation evidence and release-doctor mechanics.

Proof-backed claims

  • Vaporize gives assistant-run builds an owned proof surface.
  • Vaporize wraps Swift and Xcode workflows with release evidence and typed receipts.
  • Vaporize can validate JSON release evidence, inspect Apple project records, generate first-slice Xcode project world-state, and audit its release spine.
  • Pkl project-generation now covers app and tool target semantics, including releaseIdentity projection and Sparkle Info.plist keys.

Claims not yet allowed

  • No claim that Vaporize is faster than Swift or Xcode.
  • No fixed disk-space savings or cache-warmth promise.
  • No fleet build parity claim for Pkl-backed Xcode generation.
  • No public release approval or Sparkle appcast/signing proof.
