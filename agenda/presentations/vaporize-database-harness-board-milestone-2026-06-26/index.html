02 / Why Now

Vaporize is becoming the proof gate for real product state, not just package commands.

The Git and Savepoint audit forced the workstream to use Vaporize as the primary lane. Database state is the next category of product truth that must be tested, receipted, and promoted without leaking credentials or depending on live services in default tests.

Engineering pressure

Product-line utilities increasingly need durable state, migration scripts, and seed data as first-class test inputs.

Governance pressure

Assistants need receipts that distinguish local deterministic proof from external integration proof.

Release pressure

Board approval cannot rely on terminal summaries alone; package tests, typed records, and savepoint events must line up.

04 / CTO Architecture View

One model, two storage modes, one receipt boundary.

The architecture deliberately separates deterministic local database materialization from remote Turso configuration. The board should read this as a control surface, not as a production database client.

07 / Risk Register

The milestone is strong enough for internal adoption, not public consumption.

Resolved or contained

  • Default tests do not call Turso or any network service.
  • Receipts encode network requirement explicitly.
  • Swift 6.4 test-mode toolchain issue has a landed fix bead.
  • Savepoint presence-link enforcement worked as designed.

Open gates

  • Real Turso integration must be environment gated and separately receipted.
  • CUJ08 Concourse live-fixture expectations need refresh.
  • `realize` mode remains planned, not installed.
  • `validate-json` repeated `--path` behavior remains a documented ergonomics bug.
08 / Decision Ask

Approve the next internal phase with public release withheld.

Approve now

  • Accept CUJ21 database harness as a completed first slice.
  • Use it as the canonical local fixture pattern for database-dependent Vaporize tests.
  • Authorize opt-in real Turso integration work behind explicit env gates.
  • Require all future database proof modes to emit structured receipts.

Hold for public release

  • Do not publish this as production Turso support yet.
  • Do not allow default tests to depend on external database availability.
  • Do not promote until release-doctor covers database harness evidence.
  • Do not close the modernization workstream until `realize` and JSON validation gates are resolved or explicitly rescheduled.
